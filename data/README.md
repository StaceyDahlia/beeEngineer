# Данные MybeeEngineer

## Где что лежит

- `raw/` — исходные CSV организаторов и `norms.xlsx`. Русские имена сохранены как есть; рядом лежат короткие английские алиасы для кода. Эти файлы не редактируются.
- `reference/` — нормативы работ, типы оборудования, коэффициенты пробок и конфигурации синтетических данных.
- `processed/scenarios/east/` — сценарий «Восток»: 66 заявок, 12 инженеров.
- `processed/scenarios/southeast/` — сценарий «Юго-восток»: 83 заявки, 12 инженеров.
- `processed/scenarios/southcenter/` — сценарий «Югоцентр»: 56 заявок, 11 инженеров.
- `processed/jobs.json`, `engineers.json`, `events.json` — активный сценарий, который читает backend. По умолчанию выбран `east`.
- `processed/locations.json` — адреса и координаты активного сценария.
- `processed/inventory.json` — стартовые остатки оборудования активного сценария.
- `processed/geocoded_locations.geojson` — все точки для просмотра на карте.
- `processed/*_summary.json` и отчёты внутри сценариев — контроль качества и происхождение полей.
- `../docs/source/` — исходный PDF задания и очищенная транскрипция встречи.

## Переключение сценария

Из корня проекта:

```powershell
python scripts/select_scenario.py east
python scripts/select_scenario.py southeast
python scripts/select_scenario.py southcenter
```

Скрипт копирует выбранные `jobs.json`, `engineers.json`, `events.json`, `locations.json` и `inventory.json` в `data/processed/`.

## Что взято из исходных файлов

- заявки, адреса, районы, окна обслуживания, тип и подтип работ;
- фактический список бригад из контрольного распределения;
- адрес офиса каждого сценария;
- нормативы длительности из `Нормативы.xlsx`.

## Что синтезировано

- навыки инженеров, транспорт, смены и стартовые остатки оборудования;
- требуемое заявкам оборудование;
- коэффициенты пробок по часу и типу дня;
- три демонстрационных события перепланирования на сценарий.

Синтетические поля имеют описание в `provenance`. Генерация детерминирована (`seed=42`). Смены `10:00–19:00` и `13:00–22:00` — допущение команды, а не информация организаторов.

## Геокодинг

Координаты есть у всех 205 заявок и всех офисов. Основной источник — Nominatim/OpenStreetMap; 14 адресов проверены дополнительно по 2GIS и открытому набору Москвы. Два адреса требуют подтверждения владельцем исходных данных:

- `southeast:office`: исходное `Бирюлёвская, 1с1`, найдено `Бирюлёвская, 1 к1`;
- `southeast:loc-074`: исходное `Бирюлёвская, 44`, использован ближайший найденный дом `44/6`.

Статус точности хранится в `geocode_status`, источник и пояснение — в `geocode`. Для публичной демонстрации карты нужно сохранить атрибуцию OpenStreetMap и соблюдать условия источников.

## События

Каждый `events.json` содержит три синтетических примера для API перепланирования:

1. срочная заявка;
2. отмена существующей заявки;
3. недоступность инженера.

## Пересборка

Скрипты выполняются из корня проекта. Полный порядок:

```powershell
python scripts/prepare_data.py --csv-dir data/raw --norms data/raw/norms.xlsx --output data/processed
python scripts/generate_engineers.py
python scripts/enrich_resources.py
python scripts/geocode_locations.py --offline
python scripts/apply_geocode_overrides.py
python scripts/finalize_geocoding.py
python scripts/generate_events.py
python scripts/validate_data.py
```

Онлайн геокодирование уже выполнено. Кэш запросов не входит в командный пакет; повторный сетевой прогон нужен только при изменении адресов.
