# FRONTEND UX REPORT

Дата проверки: 24 сентября 2026 года.

## Область изменений

UX/UI-рефакторинг выполнен только в `beeline-integration`. Backend, API-контракт,
`baseline_greedy`, `ortools_vrptw`, правила приоритетов и перепланирования не
изменялись. Приложение осталось на существующем HTML/CSS/JavaScript и FastAPI.

Изменены:

- `frontend/index.html` — компоновка диспетчерских данных, карта, карточки,
  explanation, preview и обработчики взаимодействий;
- `frontend/src/ux.js` — единое форматирование чисел, дельт и человеческого diff;
- `frontend/src/plan_adapter.js` — устойчивый резервный цвет маршрута по ID
  инженера;
- `frontend/src/scenario_state.js` — сброс режима слоя карты при смене региона;
- `tests/test_frontend_ux.py` — исполняемые проверки UX-контракта и JavaScript;
- `scripts/capture_ux_screenshots.mjs` — воспроизводимая браузерная проверка и
  создание скриншотов без npm-зависимостей.

## Что изменено

### Метрики и статус

- Километры показываются максимум с двумя знаками после запятой, минуты — целыми.
- Дельты имеют явное направление и единицу: `−36,35 км`, `+30 заявок`,
  `−1 бригада`.
- Сохранены четыре компактные KPI-карточки. Под ними добавлена строка вида
  `План построен: 66 заявок, 11 бригад, 164,47 км`.
- Статус time-limited решения остаётся нейтральным: `Найден допустимый план за
  5,1 с; оптимум не доказан`.

### Карта и расписание

- Leaflet MarkerCluster группирует близкие заявки. Клик по кластеру приближает
  границы, на максимальном масштабе раскрывает маркеры.
- Клик по маркеру выбирает заявку, прокручивает и выделяет её карточку слева,
  выделяет маркер и обновляет backend explanation справа.
- Цвет маршрута устойчив для конкретного ID бригады. При выборе бригады её
  маршрут имеет opacity `1`, остальные — `0.16`; чужие маркеры также приглушены.
- Клик по карточке инженера, имени в расписании или линии маршрута фокусирует
  карту на маршруте и синхронизирует селект инженера.
- Вместо трёх неочевидных checkbox добавлен один переключатель слоя:
  `Все заявки`, `Только выбранный маршрут`, `Проблемные`, `Неназначенные`.
- На карточках инженеров транспорт и доступность стали неинтерактивными
  бейджами. Событие недоступности выполняется через существующий безопасный
  preview/apply.

### Диспетчерские панели

- Фильтры слева: `Все`, `Срочные`, `Неназначенные`, `Изменённые`.
- Карточка заявки показывает тип, окно, адрес, исполнителя и короткий статус.
  Технический ID убран из основного содержания.
- Правая панель формирует человеческое объяснение из backend explanation:
  бригада, навык, окно, окончание работы и смены, транспорт, входящее расстояние,
  время пути и ожидание.
- `job_id`, `engineer_id`, `engine`, `solver_status` и `selection_basis` находятся
  в сворачиваемом блоке `Технические детали`.
- Backend diff переводится в адресные фразы с именами бригад. Технические
  категории показаны короткими русскими метками.

### Перепланирование

- Preview называется `Предлагаемые изменения` и явно говорит, что текущий план
  не меняется до подтверждения.
- Сверху показаны до/после, четыре дельты и четыре счётчика изменений.
- Аварийная заявка вынесена в отдельную карточку с адресом, окном, длительностью
  и навыком.
- Несколько backend-событий одной заявки сгруппированы в одну фразу. Стабильный
  demo-emergency показывает пять изменённых обычных заявок и объясняет, что
  изменения сделаны ради аварии.
- Кнопки `Отклонить изменения` и `Применить план v2` визуально различимы.

### Темы и узкая ширина

- Добавлены общие CSS custom properties для поверхностей, границ, основного,
  вторичного и приглушённого текста, акцента и состояний обеих тем.
- Исправлен контраст текста в зелёных проверках, preview, сравнении и карточках.
- Длинные адреса и подписи переносятся. Расписание прокручивается внутри своей
  области; на mobile viewport страница не имеет горизонтального переполнения.

## Проверка

Запуск приложения:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Результат: `38 passed`, четыре предупреждения зависимостей без падений.
В тесты входят форматирование `165,74 км`, `15 мин`, `−36,44 км`,
`+15 заявок`, `−2 бригады`, человеческий diff, отсутствие ложных селектов и
синтаксическая проверка inline JavaScript через Node.js.

Браузерная проверка:

```powershell
node scripts/capture_ux_screenshots.mjs
```

Headless Chrome открыл реальный FastAPI UI и подтвердил:

- присутствуют все основные controls;
- фильтры вернули 8 срочных, 0 неназначенных, 0 изменённых до события и 66 всех;
- открываются карточки отмены, недоступности, срочной заявки и добавления аварии;
- кнопки baseline и OR-Tools вызывают соответствующие backend-расчёты;
- переключение `southeast → east` создаёт новый региональный план;
- клик по кластеру выполнен, затем клик по маркеру дал одну выбранную карточку,
  один выбранный маркер и новое explanation;
- выбор инженера карточкой, таймлайном и select фокусирует маршрут;
- выбранный маршрут имеет opacity `1`, десять остальных — `0.16`;
- переключатель слоя прошёл режим `Только выбранный маршрут` и возврат к
  `Все заявки`;
- preview аварии готов к apply/discard и содержит пять сгруппированных заявок;
- при mobile viewport фактическая ширина страницы равна ширине viewport,
  горизонтального переполнения нет.

## Ограничения

- Карта, тайлы, Leaflet MarkerCluster, шрифты и иконки загружаются с внешних CDN;
  для полной визуальной демонстрации нужен интернет. Backend и pytest работают
  без внешних API.
- Маршруты по-прежнему используют backend-метрики статической матрицы; геометрия
  карты не меняет расчётные расстояния.
- PlanStore остаётся in-memory, а OR-Tools — time-limited, как в предыдущих
  этапах.
- На узком экране три колонки переходят в вертикальный режим, а широкое
  расписание прокручивается внутри панели.
