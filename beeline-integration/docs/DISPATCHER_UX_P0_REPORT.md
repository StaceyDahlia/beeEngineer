# Dispatcher UX P0 — отчёт

Дата проверки: 24 сентября 2026 года.

## Что изменено

### Карта и рабочая область

- Карта увеличена на desktop и остаётся главным рабочим объектом. Правая панель стала компактнее, вторичные данные вынесены в сворачиваемые блоки.
- У каждой бригады есть устойчивый цвет маршрута. У выбранной бригады линия остаётся яркой, остальные приглушаются.
- Клик по кластеру приближает карту. Клик по маркеру выбирает заявку, подсвечивает карточку слева, маршрут и объяснение справа.
- Слои переименованы в понятные диспетчеру: «Все заявки», «Маршрут выбранной бригады», «Неназначенные», «Требуют внимания».
- Слой «Неназначенные» исключает `completed`, `done`, `cancelled` и `closed`. Это покрыто исполняемым тестом.
- Выбор бригады без специального слоя оставляет видимым весь план и только выделяет её маршрут. Слой выбранного маршрута скрывает прочие заявки и линии. Под панелью управления показана подсказка об этом поведении.
- Легенда использует те же design tokens, что маркеры и линии. Атрибуция `© OpenStreetMap` сохранена и сделана компактной; префикс Leaflet убран.

### Читаемость и представление данных

- Добавлены общие CSS-переменные для фона контролов, текста, состояний и цветов карты в тёмной и светлой темах.
- Исправлен контраст `select` и `option`, карточек, объяснений, расписания и правой панели.
- Пробег показывается максимум с двумя знаками, минуты — целыми. Дельты формулируются словами: «Пробег меньше на 35,13 км», «Неназначенных стало на 30 меньше».
- Сравнение отображается таблицей с вертикальными строками показателей. После события состояния «До» и «После» расположены отдельными карточками без переноса слов по буквам. Таблица имеет горизонтальную прокрутку внутри панели.
- Карточка заявки явно подписывает окно, длительность работ и расчётное время в пути.
- В расписании разделены поездка, ожидание, работа и перерыв; номер остановки имеет нейтральный бейдж, колонка бригады закреплена при горизонтальной прокрутке.
- Над картой показывается активный набор: источник, регион, число заявок/бригад и время загрузки. Техническое название движка убрано из основной подписи.

### Списки, объяснения и ошибки

- Добавлен фильтр «Требуют внимания»: срочные, неназначенные, риск опоздания и конфликты ограничений получают причину и, где применимо, рекомендуемое действие.
- Карточки бригад показывают рабочие состояния «Доступна», «В пути», «Выполняет работу», «Недоступна» на основе статуса бригады и её текущей заявки.
- Назначение объясняется человеческой фразой с бригадой, навыком, временем начала, окном, окончанием смены, транспортом и оборудованием. ID и внутренние коды остаются только в «Технических деталях».
- Пользовательские ошибки API больше не содержат HTTP-коды. В сценарии аварии убраны английские `preview`, backend-термины и внутренние enum.
- Статус ограниченного по времени решения: «Найден допустимый план за N сек. Глобальный оптимум не подтверждён».

### Baseline, версии и импорт

- Baseline подписан как «Базовый сценарий: порядок поступления и первый подходящий инженер».
- В сравнении показаны назначенные/неназначенные заявки, бригады и пробег. Отдельный сворачиваемый блок показывает пробег по бригадам.
- История текущей сессии хранит время, регион, источник, событие и снимок плана. Версии названы «Исходный план», «Черновик перепланирования», «Применённый план». Версию можно открыть для просмотра.
- Добавлен интерфейс `PlanHistoryRepository`; текущая реализация `PlanStore` остаётся in-memory. UI и API честно сообщают: «История хранится до перезапуска сервиса».
- Импорт поддерживает только явную замену текущего сценария. Вариант создания нового сценария disabled с пояснением о постоянном хранилище. Замена очищает старые план, историю, выборы и фильтры.

### Передача заданий

- После расчёта доступна кнопка «Передать задания бригадам».
- Она формирует локальные маршрутные листы по каждой занятой бригаде: порядок, адрес, прибытие, длительность, оборудование и статус.
- Интерфейс прямо сообщает, что уведомления инженерам не отправлялись.

## Время в пути и оборудование

Фактическая статическая модель подтверждена по `StaticTravelMatrix`:

1. расстояние по Haversine;
2. умножение на коэффициент извилистости для вида транспорта;
3. время равно расстоянию, делённому на фиксированную скорость, с округлением вверх до минуты;
4. пробки не учитываются;
5. нормативные 20 минут поверх пути не добавляются.

Маршрутная геометрия в UI используется только для изображения. Она больше не перезаписывает backend-метрики пробега и времени.

Требуемое оборудование стало жёстким ограничением и в `baseline_greedy`, и в `ortools_vrptw`. При несовместимости заявка остаётся неназначенной с причиной «Нет бригады с нужным оборудованием». Исходный набор не содержит инвентаря бригад, поэтому добавлен `data/demo_equipment.json` с явным модельным допущением: каждая бригада получает до смены один роутер и одну ТВ-приставку. Это демонстрационные данные, а не фактические данные Beeline.

## Что работает по-настоящему

- FastAPI, три региональных сценария, baseline и OR-Tools VRPTW.
- Жёсткие проверки навыка, транспорта, оборудования, окна и смены.
- Preview/apply событий с защитой от повторного и устаревшего применения.
- Выбор заявки и бригады, слои карты, кластеры, объяснения, расписание и сравнение.
- Версионная история до перезапуска процесса.
- Импорт с полной заменой текущего набора.

## Что является demo/mock

- «Передать задания бригадам» создаёт маршрутные листы только в браузере; внешняя доставка отсутствует.
- Набор оборудования бригад — демонстрационная конфигурация.
- Линии на карте служат визуализацией; планировщик использует общую статическую матрицу, а не онлайн-навигацию.

## Ограничения и следующие production-шаги

- История и PlanStore остаются в памяти процесса. Для дня/недели/месяца нужна БД и реализация `PlanHistoryRepository` с политикой хранения.
- Нужна интеграция передачи маршрутов с мобильным приложением инженера или HelpDesk, включая подтверждение доставки.
- Статическую матрицу нужно заменить реальной матрицей времени в пути с дорожной сетью и пробками; потребуется версионирование провайдера и времени расчёта.
- Импорт пока заменяет текущий сценарий. Создание отдельного набора требует постоянного хранилища и идентификатора набора.
- UI загружает Leaflet, Tailwind, Lucide и тайлы OpenStreetMap из сети. Для полностью автономного показа зависимости и тайлы нужно поставлять локально.
- OR-Tools ограничен по времени и возвращает лучший найденный допустимый план; математический глобальный оптимум не гарантируется.
