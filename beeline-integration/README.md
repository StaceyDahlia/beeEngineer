# Beeline Business — диспетчер маршрутов

Demo-ready прототип на FastAPI: официальный `baseline_greedy`, приоритетный
`ortools_vrptw`, три независимых региона, карта и расписание, backend
explanations, безопасный preview/apply событий и история версий плана.

## Запуск

Из корня workspace:

```powershell
cd beeline-integration
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Открыть `http://127.0.0.1:8000/`. Тесты запускаются командой
`.\.venv\Scripts\python.exe -m pytest -q`.

## Демо на 5–7 минут

1. Показать выбор региона в шапке: `east`, `southeast`, `southcenter`. При
   переключении создаётся новая v1, а plan ID и история предыдущего региона не
   используются.
2. Нажать «Базовый план». Объяснить официальный алгоритм: входной порядок
   заявок и первый допустимый инженер.
3. Нажать «Построить план». В правом блоке сравнить назначенные заявки, число
   инженеров и пробег baseline с OR-Tools. Статус «Найден допустимый план…»
   честно сообщает, что оптимум не доказан.
4. Выбрать заявку на карте или в списке. Справа показать backend explanation:
   проверку навыка, транспорта, клиентского окна, смены и влияние входящей дуги
   на маршрут.
5. Нажать заметную кнопку «Запустить демо-сценарий аварии». Она создаёт свежую
   v1 `east` и воспроизводимый preview: 17.08.2026 в 19:30, Москва,
   пер. Маяковского, д. 2, skill `emergency`, 80 минут, окно до 21:30.
6. В preview показать добавленную аварию и пять обычных заявок, которые сняты,
   переназначены, переставлены или задержаны. Текущие `in_progress`/`en_route`
   этапы остаются за своими инженерами.
7. Нажать «Применить и создать v2». Карта и расписание переходят на v2, а в
   истории доступны исходная и новая версии.

Консольное воспроизведение без HTTP и внешних API:

```powershell
.\.venv\Scripts\python.exe scripts\compare_baseline.py
.\.venv\Scripts\python.exe scripts\run_demo.py --apply
```

## Что гарантирует прототип

- жёсткие ограничения навыка, транспорта, клиентского окна и окончания смены;
- открытые маршруты из стартовых точек инженеров;
- приоритеты `emergency > connection > repair/local > additional order`;
- одна общая статическая матрица и одинаковые нормы для baseline и OR-Tools;
- независимость регионов и понятные причины неназначения;
- preview не меняет текущий план, apply создаёт новую версию ровно один раз;
- завершённая и текущая работа не перепланируются, меняется только хвост.

## Ограничения

- матрица расстояний и времени статическая, без реальных пробок;
- PlanStore хранится только в памяти одного процесса и очищается при рестарте;
- OR-Tools ограничен по времени и возвращает лучший найденный допустимый план,
  не обещая глобальный оптимум;
- нет телематики, постоянной БД, производственного routing API, складского
  учёта оборудования и зон обслуживания;
- карта, тайлы и ручное геокодирование адреса в форме требуют внешних сервисов;
  backend, тесты и фиксированный demo-emergency работают полностью офлайн.
